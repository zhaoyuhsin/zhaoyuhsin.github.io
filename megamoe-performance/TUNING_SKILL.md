# 调优 SKILL

适用于本项目的 MegaMoE 性能实验。目标、当前候选和下一步以项目状态MD为准；最终性能结论进入离线看板。这里只维护能改变下一次实验决策的方法，不按实验次数判断进展。

## 1. 固定对照，再找差距

- 参考必须是布局优化 DS。记录实际源码、头文件、SO/JIT哈希和加载路径，不能只看分支名。
- 对齐 EP、每卡BS、H/I/E/top-k、共享专家、输入/权重精度、量化/scale、路由与seed、预排是否计时，以及硬件/turbo/CANN。
- 分开记录完整通信kernel、纯计算诊断、主机端到端和timer跨度。固定采样规则；本项目常用warmup10、采20取后10，同时保留逐轮rank-min和rank-max。
- 一个启动中的20次调用不是20次独立实验。先单因素筛选，再用ABBA等同窗口交替复测；不能把不同父版的收益相加或按shape挑分支拼最优曲线。
- 先把双方MegaMoE拆成头开销、GMM1、GMM2、Dispatch、Combine、SwiGLU及必要的尾段，对比分项耗时和关键路径位置，优先找差距最大的部分。统一首尾边界、任务覆盖和ISSUE/完成语义；阶段可重叠，不能把累计耗时直接相加当端到端。

## 2. 完整被动timer：清晰且不过度扰动

- 性能允许关闭timer，或采用通过开销复核的完整被动timer。双方口径一致；每次timer-on采样调用都要真的打点，不能只打最后一次来稀释开销。
- 默认仅rank0打点，但保留32组 AIC/AIV0/AIV1、GMM1/GMM2 Prologue、Dispatch、SwiGLU、Combine及首尾阶段。不要默默关闭AIV0或只采6组。
- 复用已有完成边界，只读时钟、写必要记录；不为测量增加FIX→Scalar、PIPE_ALL或逐K排空。异步提交区间明确叫ISSUE，不伪装成完成时间。
- 开销目标2–3%以内，必须按实际shape/候选复核。历史BS96完整被动版曾约1.43%（仅rank0）、2.02%（全rank）；不是所有配置的保证。
- JSON保留真实时间与核心/角色映射，按group数值排序。等待可以在派生图隐藏，但不压缩时间；原始数据保留等待。全核空白、未采集和真正等待必须区分。
- 保存JSON发生在主机侧，不等于设备打点成本；优先减少重复元数据，不能靠缩小JSON宣称kernel变快。每次流水与该批CSV/版本配对，本地归档并校验。

## 3. 分核profiling：先区分角色

诊断时优先开启 `--task-block=on`，例如在支持该入口的工具版本中：

```bash
msprof --task-time=on --task-block=on --aic-metrics=PipeUtilization --type=text --output=独立目录 运行命令
```

- 先核实工具版本、支持参数、metric组和实际导出字段；`task-block`不是“自动获得所有计数器”的开关。可能需要分组采集、读取原始数据或官方数据库。
- 从真实核类型/sub-block映射 AIC、AIV0、AIV1，不猜奇偶核。AIV0重点查权重 GM→UB、FP4转换、UB→L1；AIV1重点查Dispatch、激活、Combine和归约。
- 按相同角色对比双方AIC、AIV0、AIV1的指标，结合活跃时间、利用率、流量和每任务/每字节成本定位异常；不要只看全核平均，也不要把角色工作量不同造成的差异直接当作低效。
- 按支持范围采：MAC/FIX、Scalar、Vector、MTE1/2/3、读写量/带宽、L2请求与hit/miss、UB冲突。保留原始CSV、sample/事件映射、数据库及有效配置；缺失指标不能填0。
- Scalar长不等于全是等待；MTE长也可能受下游反压。MAC/MTE/Vector活跃时间会重叠，不能相加解释端到端差距。
- UB写冲突事件表示访问争用线索，不代表数据写错，也不能直接换算成损失周期。L2命中率要结合请求量；带宽要核对字节倍率和统计分母。
- 分核PMU计数通常覆盖整个kernel，不能冒充某一段GMM的计数。重采后用干净、同口径的完整kernel测试验收，避免把profiling扰动算成优化收益。

## 4. 把线索变成可证伪的实验

- 极限调优遵循木桶效应：从整体推理关键路径确认当前瓶颈，再判断是计算、带宽/供数、同步/调度还是通信/尾段bound。用流水依赖、PMU和单因素实验交叉验证，优先缩短不能被隐藏的部分；最高利用率或最长累计区间不一定是瓶颈。每轮有收益后重新判断bound，避免继续优化已非短板的模块。
- 先问差距在连续任务内部、阶段切换，还是启动/尾段。连续GMM长条不证明MMAD连续；ISSUE之外不自动等于空泡。
- 两者GMM都慢而短K更吃亏：检查固定成本、供数接续、L1/L0复用及输出重叠；不要只增加buffer。
- 请求数接近而MTE时间更长：检查GM/UB地址、stride、段长、padding和槽位组织；把布局、DMA分段和同步分开测试。
- ISSUE已接近而完整kernel仍慢：检查ready发布、完成边界、消费者推进和尾段；优先在DS上反向消融，明确干预是否等价。
- 每项实验写清：父版、单一假设、改动边界、预期变化、反证和停止条件。结果无收益就降低优先级，不连续换小参数而不更新判断。
- 大规模迁移先复现完整参考终点，再按数据ABI/事件所有权闭合包做正反向消融；不是按文件行数二分。有效组合再撤销其中一项，以免把修复新增回退算成净收益。布局、缓存和计算leaf可形成四格对照，但必须保持同一数学合同。

## 5. 同步和跨EP不能省略

- 对每个缓冲明确生产、消费、真实完成、最后读取完成和释放credit。issued、可见、可复用不是一回事；不能删必要等待或提前覆盖输出换性能。
- FIX→UB省GM往返，但可能增强生产者/消费者反压。对照保持双credit，避免把修复新增单槽回退算成净收益。
- 均匀路由下每专家M约为 `EP × BS × top-k / E`。每卡总接收量期望可近似不变，但专家数、尾块、复用和通信拓扑在变；EP8收益不能外推到大EP。
- 多机回退时可调整EP/E，保持本地专家数和每专家M一致做单机诊断；明确改变了模型/拓扑，不写进目标shape曲线。单机候选与父版接近，只降低纯后端解释的优先级，不排除供数与远端通信的交互；不能把单机/多机耗时相减当通信成本。
- 用户仅性能时记录未跑独立Golden；有限值/逐位差分只证明对应回归范围。布局和同步变更在推广前补尾片、空专家、偏斜路由和目标EP正确性。

## 6. 已验证的反例与本轮教训

- 首GMM2提前约38μs，但完整kernel只改善约10μs：更早开始不等于更早结束。
- BS1024 DS阶段排空增加约53μs，但它每核29次，我们仅8个wave；接近8次频率的对照只增加约15.5μs。频率相近仍不等于完整协议等价，不能承诺等额回收。
- 增加排空后ISSUE累计反而缩短、完整kernel却变慢：等待改变了反压归属。不能把ISSUE变短直接当作计算后端更快。
- 比较credit要换算成行数/字节和完整任务数：两个“整tile”GM credit改成两个半tile CV槽，数量仍是2，有效数据深度却可能减半。迁移参考实现时连同生产粒度、消费量子、驻留输出和释放边界一起核对；小M收益不能直接推广大M。
- 输入最后读取与输出最后写出是不同边界：只读CV输入加独立输出scratch，和输入/输出共用CV槽，释放条件并不相同。按真实owner证明，不因参考实现用了某条管线就照搬归还时刻。
- 资源条件需要分形状策略时，形成一个共享规则并冻结同一SO统测；不能拼各分支最低值。用均衡期望M选路时注明它不是实际最大专家M，偏斜路由要另验；修复新增回退不算相对有用父版的净收益。
- 本轮权重SF排列的正反向证据强于“C API天然比TLA快”的猜测；新leaf撤销后布局收益仍保留。分别检查权重SF和激活SF，不把两者统称为scale布局；原始位模式/shape不变也可能改变GM物理访问。尚无PMU时不宣称已量出带宽/cache改善。
- 缓存按真实复用范围分类：当前slice M小，不代表完整专家没有跨M复用。布局重排与缓存hint分开消融；改prepared布局后，旧缓存及混装Python/native须在正式集成前明确拒绝。同seed、同负载但不同输入生成器，不等于同一组原始输入字节。
- 迁移前建立逐rank原始FP8/FP4/SF/路由权重SHA桥接，再分别冻结两侧数学输出。前置加权、激活舍入和MX scale规则不交换；跨合同RMSE单列，不能把改数学当作原规则等价优化。完整数值迁移后可再做逐位差分，但它仍不是独立Golden。
- 搬计算函数要连同调用者状态审查：一次反向移植因漏掉FP8转换的CTRL位而全部NaN，补齐后才与原输出逐位一致。函数源码相同不证明溢出模式、布局、事件和调用前置条件相同。
- 反向恢复ours数值规则曾让DS明显变慢，但正向采用DS规则没有等额收益；尾部归约粒度与加权位置存在交互。反向代价不是可直接迁移的收益上界，必须在我方框架实测，并在数值合同变更后重建瓶颈账本。
- 新增预取、metadata缓存或共享证书时，完整kernel必须计入新增搬运、完成等待和同步。不要只统计随机远端读消失后的局部区域；共享地址必须配套唯一writer、真实完成发布及所有reader的可见性。
- 共享计数表的反例：约50μs回退位于首GMM前，给每核独立完成flag仍不能挽回；因此“单flag争用”未获支持。继续将全表扫描改为预计算证书时，既比较共享表失败父版，也比较迁移前有用父版，区分回收回退和净收益。
- “对齐布局”要检查实际层级：权重SF、FP4本体、激活SF和通信记录是不同数据ABI。已有SF正收益不证明FP4预排同样有效；无论迁移到哪一层，都同时核对writer/reader、容量与版本，并重新测完整kernel。
- 远端长测冻结脚本路径和字节，不能运行中覆盖Bash文件。重试保留旧失败状态，用新节点；源码上传先核对完整SHA。设备测量有效性与控制器返回码分别审计，不能静默改写失败记录。
- 先确认优化路径真的启用：rail快路由在当前版本仅用于BS≤256，把它改快不能解释BS512/1024；同一VF覆盖Direct后才是对应shape的有效实验。
- 发射成功、kernel运行成功和有效性能行是三个门槛。SIMT迁移必须核对动态shared、静态区、VF栈及手工UB布局；只有alignment kernel的CSV不能算MegaMoE变快。失败即保留原始runtime日志，不能放宽kernel筛选掩盖异常。
- CPU指令桩要先核对实际overload的地址单位；同名Gather并不等价。[Reg Gather的索引是元素](http[机器本地路径未公开])，GatherB是字节偏移。用非均匀位型、尾向量和保护区测试，不能只用均衡常数数据验证地址公式。
- 计时边界以原始区间为准，而非外层C++作用域：本项目EndWait会重写tile ISSUE起点，实测WAIT和ISSUE不重叠。把预取移到WAIT之前后，一部分工作会进入未分类区间；不能把ISSUE下降全部称为纯计算收益。用区间并/交集检查，并以完整Duration验收。
- R32带权metadata的反例：单份BS512流水中Dispatch ISSUE约120→57μs，但完整kernel两轮均值回退约7μs；供数组合R33仍没有净收益。局部成本可能被重叠，等待归属也会改变；不能强行保留“更像DS”的机制。独立无益也不自动排除瓶颈变化后的组合，组合必须实际测。
- 跨EP二分先确认改动的真实边界：旧master的大BS GM Combine也是双槽，不能因全局上限6便误报6→2。若C5在多机已慢于master，就把二分前移，不再把全部损失归到C5之后的FP4布局。缓存/布局诊断与通信调度诊断分域留档。
- 保留、拒绝或待验证都记录理由。凭据不入文档/网页/Git；只用空闲卡，不终止他人程序。每轮更新项目状态、性能证据和本SKILL。
