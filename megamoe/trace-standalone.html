1. Shape 与字节口径

路由：均衡（当前支持）。默认 FP8 Dispatch；Combine 不量化，BF16 每元素2 Byte。N 不影响通信字节。仅支持 Base 每路由一行；去冗余或量化 Combine 需另行核对字节公式。核组数要填真实配置，不能改为文件里截取的核数。再次打开会恢复上次设置，可点击“恢复默认配置”。

2. 如何解释带宽

每核字节采用 Rank 总字节 / 参与 AIV1 数，是均分估算，不按事件次数分摊。

不同 Tile/Token 调度可能导致分工不均；Trace 没有逐核字节时无法声称这是硬件实测带宽。

“Rank折算”只是用全 Rank 字节除以时间的指标。逐核带宽相加、累计核时带宽、墙钟带宽是不同量，不能混用或直接与140 GB/s比较。

指标DispatchCombine
V 为单 Rank 所选范围的全量字节，C 为配置核数，P 为有记录核数，Tᵢ 为单核累计时间：
已导入核带宽之和 = Σ[(V/C)/Tᵢ]；分摊累计核时带宽 = [(P/C)×V]/ΣTᵢ。
全核平均累计时间折算 = V/(ΣTᵢ/C)；仅全核都有正耗时记录时显示。
墙钟并集带宽 = V/所有通信区间并集长度；阶段包络带宽 = V/(最晚结束−最早开始)。
Byte ÷ μs ÷ 1000 = GB/s。分摊带宽相加不是 NIC 墙钟吞吐；并集仍是打点活动区间，不是链路 PMU。
