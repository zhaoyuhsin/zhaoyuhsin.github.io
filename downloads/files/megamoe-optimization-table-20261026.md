# 从最早 main 到当前分支：优化分类、收益与适用倾向

更新：2026-10-25。本表只整理历史证据与当前代码，不启动新实验。

> 发布说明（2026-10-26）：本表保留2026-10-25的历史证据口径。“当前分支”固定指Wave+GM原生提交`095b4c7f`；2026-10-26该分支已快进成为个人仓库`main`（提交`7de059f`）。升级main不代表已证明全EP/全BS最优，表内风险与缺测说明仍然有效。

## 比较边界

- **起点：历史 main24，`24b42213`。** 这是此前EP32/BS4096约4603μs所指的main，不是移动中的main分支名。
- **终点：Wave+GM，原生`095b4c7f`，分支`codex/megamoe-wave-gm-1025`。** 它继承Wave/CV `4a0de857`的主体，再统一关闭CV；不能把最新实验分支称为已证明最优版本。
- 更早的`8ffafeb`是另一条“计算优化前main”基线。GMM2流水复用、GMM1异步完成在main24里已经存在，下面单列为基础，不重复计入main24之后的新增收益。
- 固定模型：H7168、I3072、E384、top-k6、共享专家0、FP8激活/FP4权重。BS为每卡输入token数。

**收益不是相对main24的一张可加账单。** 每行写的是当时对直接父版本的消融；父版本、CANN、机器和测量方式不完全相同。今天撤掉该项会损失多少，仍需在今天的组合上反向消融。当前没有main24与095在同一窗口完成的全EP/全BS总对照，不能据此宣称总共提升多少。

证据标签：**双启**=每种方法两次独立启动；**筛选**=历史单次或非严格成组对照；**无隔离数值**=不能归给该项单独收益。主表未注明时均为EP8完整通信kernel、timer-off的历史记录；纯计算另标。不同表中的收益不可相加。

### 怎么读“大小EP倾向”

在当前E384/top-k6的均匀路由期望下：

`每专家M ≈ EP × BS / 64`，`每卡专家数 = 384 / EP`。

例如BS512时，EP8/32/64/128的期望M分别为64/256/512/1024。因此小M供数方案在EP8有效，不保证同BS到EP128仍走同一物理路径；相反，多M块权重复用、专家数量减少、通信拓扑和尾波都发生变化。

主表EP列除明确实测外都是机制倾向，不是跨EP收益证明。当前最缺的是相同版本、相同拓扑合同下的EP64/128单项或组合验收。

## 综合评价：哪些最值得留下

### 1. 基础性较好，但不叫全shape必赚

FP4等价解包、输入/输出独立生命周期、兼容资源handoff、真实FIX的消费者等待、生产/消费布局一致性。这些解决的是明确的冗余或所有权问题，适合作为长期框架。**“机制合理”不等于已证明每个EP都正收益。**

### 2. 当前最需要按资源条件使用的策略

gate/up配对、Wave预算、GMM2 lag、小M K/N计划、缓存和credit配额。这些没有脱离条件的好坏：

- 小BS扩大Wave，主要摊薄固定开销；大M配对后缩Wave，主要减少下游启动/收尾延迟。
- lag不是延迟越少越好，而是给GMM2留足输入提前量；小BS不一定有足够工作把等待摊掉。
- 配对没有减少GMM数学FLOPs，收益来自任务组织和衔接；失配的Wave/ready粒度可以反过来造成回退。

**我最看重的近期证据是：两轮Wave预算与中大BS lag。** 它们既有较大的局部收益，也有小BS/错误预算的反例，因果解释比“把DS更多代码搬过来”更具体。

### 3. 单项收益弱，优先保持简单

Scalar metadata微调、物理分核小调整、部分缓存提示、CV/GM选择。它们可以是当前组合的合理部分，但在没有新的反向消融之前，不应在汇报中各算一条显著收益，更不应继续为0.x%的不稳定变化增加多条执行路径。

### 4. 当前不能宣称的结论

- 没有main24到当前版本同窗的全矩阵总收益；不能把上表各项相加。
- 新分支不等于最优；Wave+GM尚有EP32/1024回退风险。
- 当前slice ready不等于细粒度token-prefix提前归约。当前AIV1在收到Wave真实完成事件后重放并发布slice计数，仍可能存在消费者就绪粒度的优化空间。
- “保留原数学/输出差分一致”不等于所有版本都通过独立Golden。历史部分试验做过精度，近期按要求仅作性能和指纹回归；不能继承成当前全矩阵精度PASS。
